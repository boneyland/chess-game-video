# Chess Replay

Browser player for annotated chess games: the claude.ai artifact and https://chess-replay.onrender.com/. Split out of `~/projects/chess-animator` (Python/Manim renderer) on 2026-10-17; that repo must stay checked out next to this one.

## Commands
- `node build.cjs` - writes `out/chess-game-video.html` (artifact, engine inlined) and `out/site/` (page, two Stockfish files, two WebP encoder files, web app manifest + icons from `app/icons/`, service worker `sw.js` (from `app/sw.js`), link-preview image `app/og-image.png`, 1200×630, whose `og:image` URL is Render's `RENDER_EXTERNAL_URL`, or the Render site in a local build)
- `node --test --test-concurrency=1 tests/*.test.cjs` - JS tests (also writes `tests/out/`); GitHub Actions (`.github/workflows/test.yml`) runs them on every push, and the Render build before building
- `node --test tests/live/site.test.cjs` - smoke tests against the live site in Chromium, then Firefox (Playwright, real mouse input; screenshots in `tests/out/live/`). `LIVE_URLS=local` tests a build of this checkout served by `tests/live/serve.cjs`, `LIVE_BROWSERS` picks one browser, `LIVE_CDN_DIR` serves React from local npm packages where cdnjs is blocked, `FIREFOX_PATH=playwright` runs Playwright's own Firefox (a cloud machine without a stock Firefox). Here: sandbox disabled, Playwright via `NODE_PATH` (an npx copy under `~/.npm/_npx`); Chromium is the ungoogled-chromium flatpak, Firefox the installed Developer Edition over WebDriver BiDi. GitHub Actions runs it with `LIVE_URLS=local` in the runner's Chrome and Firefox (`browsers` job, Playwright pinned there). Never in deploy builds
- `../chess-animator/.venv/bin/python -m unittest tests/check_browser_json.py` - checks the browser's analysis JSON against the Python pipeline; run after the JS tests
- `node media/record-demo.cjs` - re-records `media/demo.mp4`, the README's ~65 s showcase video, zooming in on the panels worth reading (Byrne–Fischer 1956 from `media/demo-game.pgn`), from a build served by `tests/live/serve.cjs`; sandbox disabled, Playwright via `NODE_PATH`, ffmpeg. GitHub plays a README video inline only when uploaded through its web editor, so a new recording is dragged into the README there
- Preview: `node tests/live/serve.cjs` (out/site on 127.0.0.1:8765, answering as Render does) with the sandbox disabled (a sandboxed server is unreachable from Playwright, and `file://` is blocked); phone layout = 390×844 viewport

## Publishing (only when asked)
1. Artifact: publish `out/chess-game-video.html` to https://claude.ai/artifact/5yXwsRkre66WZZ8AEmLrqT (Artifact tool, `url` set). In a new session the first publish is refused and returns the live diff; check it holds only your changes. The next unchanged resend is refused too (a deliberate double-check); send it a third time and it goes through
2. Render: a static site (chess-replay) built from this repo on every push to `main` (publish `out/site`). Its settings live in `render.yaml` (build command with the tests first, rewrite `/` → `/chess-game-video.html`, Cache-Control header, build filters): the service is linked to a Blueprint, so a push that changes the file syncs them; change them there, not in the dashboard. Auto-deploy is on, so a merged PR that touches the page goes live there at once

## Workflow
- Since 2026-10-19: work goes on a branch (`claude/<topic>`) as small commits, pushed with a pull request against `main`; never commit to `main` directly. Merging the PR is what deploys (Render builds `main`). Remote is `origin` (github.com/boneyland/chess-replay); push and open the PR only when asked
- Visual changes: screenshot desktop (1440×900) and phone layouts and show the PNG paths before committing; the user usually tweaks sizes
- Screenshots taken for a change go in its PR description too, each with a caption (viewport, browser). `gh` can't upload attachments, so they live on the orphan branch `pr-screenshots` (no workflow files, so no CI; Render builds only `main`) under `pr-<N>/`, embedded as `https://github.com/boneyland/chess-replay/raw/pr-screenshots/pr-<N>/<file>.png`. Add them with git plumbing, leaving the working tree alone: a temporary `GIT_INDEX_FILE` seeded from the branch tip (`git read-tree origin/pr-screenshots`), `git hash-object -w` + `git update-index --add --cacheinfo`, `write-tree`, `commit-tree -p origin/pr-screenshots`, then `git push origin "<sha>:refs/heads/pr-screenshots"` (quote it: zsh reads `$c:r` as a modifier)
- The user views the app in desktop Firefox. Checks here can run in Firefox too (Developer Edition, `firefox.launch({ channel: 'moz-firefox', executablePath: '/usr/bin/firefox-devedition' })`): for layout changes (CSS columns, overflow, height caps) screenshot both browsers; a capped-height multi-column box once spilled a fifth Settings column in Firefox that Chromium never showed. Playwright's Firefox has no phone emulation (no `isMobile`, a fine pointer), and its headless full screen is a 1366×768 screen
- Board/overlay checks: drive with real `page.mouse` input, not `dispatchEvent` (synthetic events once hid an overlay swallowing taps)
- Long one-line statements (some over 200 characters in `game-video-core.jsx`, `queen.jsx`, `chess-core.js`) are known debt from the 2026-10-17 tech-debt audit: split them only in code you are already changing, never in a sweep of their own
- Render's deploy build runs the full test suite, real-Stockfish test included, on purpose: it stops a broken push going live. If that test ever fails a deploy spuriously, skip just it in the deploy build and leave it to GitHub Actions

## Gotchas
- Layout lives in `app/game-video-core.jsx`: `LAYOUTS.wide` is the 1920×1080 frame, `tallLayout(H)` the 840-wide phone frame (scaled to fit, so phone text reads smaller); the frame's outer padding is `.stage-tall` in `app/shell.html`
- The Full screen menu item shows only where `document.fullscreenEnabled` (or the `webkit` one) is true: not on iPhone Safari, whose way out of the bars is Add to Home Screen (the manifest)
- Settings defaults are `window.TWEAK_DEFAULTS` in `app/shell.html`; viewers' changed settings persist in localStorage and override new defaults
- Move numbers and sides come from `M.ply0` (`ChessCore.moveNo`), never `i % 2`; squares become pixels only through `view()` (the board can be flipped)
- The free board (the dock's Play/Explore menu: Starting position, Paste FEN…; stored files `{ board: { fen, moves, upto } }`, `app/free-board.jsx`, state in `BoardCore` (`app/board-core.js`)) is a separate view from `GameVideo`: the replay's timeline never sees a zero-ply game. Both take board input through `useBoardInput`; the transport bar runs in `still` mode there
- A game (Play vs human) is a free board with a game record (`board.game`, rules and clocks in `PlayCore`, `app/play-core.js`), stored with the board. During a game `FreeBoard` starts no Stockfish search and draws no eval bar or explorer (the spec's anti-goal); the board is turned to the side to move whatever Flip says
- My games: each game (`board.game.id`) is kept from its first move under `chess-video.games.v1` (`GamesCore`, `app/games-core.js`; the 50 newest, as `BoardCore.save` boards) by `commitBoard` when the game changes (a move, takeback or result; not stepping through it), reading the stored list afresh each time; `GamesCore.read` checks only the shape (it runs on every move), `GamesCore.playable` restores an entry for the dialog. A finished game opens as a loaded game from `PlayCore.pgn`; the crash screen's Clear saved data leaves the list alone
- Hugging Face sign-in returns to the folder the page is served from (`HF_OAUTH.redirect` in `app/queen.jsx`); every such URL must also be listed in the HF OAuth app's redirect URLs (huggingface.co/settings/applications), exactly, trailing slash included
- Ask Queen calls the user's HF Space boneyland/queen-pawn-8 (`gr3_queen_pawn_8_analyse_position`, `{fen, moves}`) via the artifact's `mcp` capability; its answer is a Python dict repr (`pyParse` in `app/queen-core.js`). ZeroGPU quota is small (~20–33 s per position): never suggest whole-game Queen runs without the cost
- Not on Netlify: dropped 2026-10-18 (production deploys cost credits, which ran out, and publishing was manual). Don't add Netlify config back
- Not on Codeberg: its Terms of Use (§ 2 (1) 7) forbid projects mostly written by generative AI, which this one is (tried and taken down 2026-10-17)
- `vendor/` is stockfish.js v19.0.1 lite-single (GPL-3.0) and the WebP export's encoder (libwebp 1.1.0 in WebAssembly, from @jsquash/webp 1.5.0, its deblocking filter off in `WEBP_CONFIG` in `app/export.jsx`: the browser's own `toBlob` encoder blurred some frames), pinned by SHA-256 in README; the site serves both next to the page, so the artifact's WebP export doesn't work; `openings/` is a copy of chess-animator's Lichess tables
- Offline: the site's `sw.js` keeps the page (network first) and everything it loads, CDN files and fonts included (from the copy first). Its `VERSION` is a hash of those files, so a deploy that changes one replaces the copy; a new CDN URL in `shell.html` or `export.jsx` is picked up by `build.cjs`. The artifact registers no service worker. Playwright's offline emulation in Firefox fails `no-store` requests a service worker answers; stopping the server is the real test
- `docs/` (browser Stockfish design/plan) predates the split; its paths have been rewritten to repo-root ones
- `games/` (local PGNs) and `.superpowers/` (scratch) are untracked; never commit them
